# 项目架构说明

这个仓库是一个「个人主页 + 技术博客 + 项目展示」的**全栈学习项目**。
它刻意做成了「学习展示柜」的样子：真实能跑的代码 + 大量注释 + 文档。

## 整体关系

```
                        ┌─────────────────────────────┐
   浏览器 ──────────────▶│  GitHub Pages（静态托管）     │
                        │  └ 根目录 index.html         │
                        │     你正在看的静态主页         │
                        └─────────────────────────────┘

   浏览器 ──────────────▶│  frontend/  React + Vite     │  本地 npm run dev
                        │  （个人主页/博客/项目的示例）   │
                        └──────────────┬───────────────┘
                                       │ 请求 JSON
                                       ▼
                        ┌─────────────────────────────┐
                        │  backend/   FastAPI          │  本地 uvicorn
                        │  /api/posts /api/projects…   │
                        └──────────────┬───────────────┘
                                       │
                                       ▼
                        ┌─────────────────────────────┐
                        │  SQLite（本地）/ PostgreSQL    │
                        │  （docker-compose 预留）      │
                        └─────────────────────────────┘
```

## 各部分职责

### 根目录静态主页（`index.html`）

- **谁在跑它**：GitHub Pages，全世界都能访问。
- **干嘛的**：你的门面。纯 HTML/CSS/JS，零依赖零构建，改完推 GitHub 就上线。
- **现在**：除了展示个人介绍，还加了「项目结构」区块，指引访客去看文档和源码。

### `frontend/` —— React + Vite

- **谁在跑它**：目前只在**你本地**跑（`npm run dev`）。GitHub Pages **不会**构建它。
- **干嘛的**：用现代前端框架重写一遍个人主页，作为你学习 React 的练习场。
- **数据从哪来**：先写在 `src/data/*.js` 里（模拟数据），
  将来可以改成请求 `backend` 的接口。

### `backend/` —— FastAPI

- **谁在跑它**：目前只在**你本地**跑（`uvicorn app.main:app --reload`）。
- **干嘛的**：提供示例 API（`/api/health`、`/api/posts`、`/api/projects`），
  让你体验「前后端分离」是什么感觉。
- **数据库**：本地 SQLite（零安装）；docker-compose 里预留了 PostgreSQL。

## GitHub Pages 能做什么 / 不能做什么

**能：**
- 托管纯静态文件（HTML / CSS / JS / 图片）
- 自动构建流程（`pages.yml` 里未来可以加，目前用默认部署）
- 绑定自定义域名

**不能：**
- 跑 Python / Node 服务端代码 —— Pages 只做「把文件发给你」的事
- 动态处理请求、写数据库 —— 这些都必须交给真正的服务器（VPS / Render / Railway…）

所以：**根目录静态主页能直接上线；`frontend` 和 `backend` 需要你自己在本地跑，
或者将来部署到 Vercel / Render 等平台。**

## 为什么不「一步到位」直接全用框架？

因为你是**新手**。这个项目的设计哲学是：

1. **先看懂**：纯 HTML 的 `index.html` 一眼就能看懂，改一行字就能看到效果。
2. **再进阶**：React 前端给你框架的感觉，但数据是静态的，不涉及复杂状态。
3. **最后全栈**：FastAPI 后端给你 API 的概念，但结构简单、没有权限系统。

一步一个脚印，慢慢来，比较快。
